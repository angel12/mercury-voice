# Mercury Voice engineering audit

## Summary

- **46 findings: 11 fixed, 35 intentionally left unchanged.** Findings include demonstrated bugs, static-trace bugs, potential bugs, duplication, unused-code candidates, and test/maintenance gaps; they are not 46 reproduced production failures.
- **Eight bug fixes**, including one test-infrastructure bug; one duplicate helper consolidation, one redundant `await` removal, and one documentation correction.
- Baseline: **`6cd7a539292936d2a8605b865de638b08e4fb4c8`**. Fixes, regression tests, and this report were committed in **`6db1c5d`** and published in [PR #51](https://github.com/angel12/mercury-voice/pull/51). Remaining findings were not automatically filed as issues.
- Baseline tests: **224 tests / 37 suites**. After fixes: **236 tests / 40 suites**, including a successful Thread Sanitizer run. Parameterized cases are counted using Swift Testing's reported test totals, not as separate test declarations.
- Overall: clear module boundaries, no third-party dependencies, good pure-model/voice-state coverage, but **substantial lifecycle and integration risk remains**. Package tests do not establish correctness of app controllers, real network reconnection, or audio hardware. This is not a release-readiness sign-off.

## Phase 1 — Architecture and coverage

### Dependency and data-flow map

1. `MercuryVoice/MercuryVoiceApp.swift` starts the multiplatform SwiftUI app. All windows share `AppModel.shared`. `RootView` selects Connect → Browse → Conversation and forwards foreground recovery signals.
2. `AppModel` owns endpoint selection, credentials, the `HermesConnection`, browse/profile loading, and the current `ConversationController`.
3. `HermesKit` owns endpoint normalization, Keychain credential storage, password/native-PKCE authentication, REST, single-socket JSON-RPC, reconnect supervision, session/project methods, replay and provider configuration models.
4. `ConversationController` translates connection events into app state, approval/question sheets, and a serial tracker event stream. `AgentTurnTracker` accumulates assistant bubbles and busy/spoken watermarks. `ConversationEngine` is the actor-based voice state machine.
5. `AudioCaptureService` broadcasts microphone chunks. `MicRecorder` handles normal VAD; `BargeInMonitor` detects interruptions and records pre-roll. Rate-locked resampling prevents route changes from changing the sample-time basis.
6. Captured audio → direct-provider or relay STT → stop/echo checks → `SessionAPI` prompt submission. Gateway reply events → tracker → direct sentence TTS or relay PCM streaming → whole-clip fallback if required → re-arm.
7. `Shared/ConversationActivitySupport.swift` supplies ActivityKit attributes and intents to both the app and `MercuryVoiceWidgets`. App shortcuts, hotkey, keep-awake, device selection, and activity synchronization are platform adapters rather than independent services.

The SPM package exports **HermesKit** and **VoiceEngine**; VoiceEngine depends on HermesKit. There are no third-party package dependencies. The Xcode app consumes both; its iOS-only widget dependency consumes Shared source. No database or backend service is implemented in this repository.

### Coverage boundary

The baseline has **106 tracked files**, including **77 Swift files**: 14 HermesKit sources, 23 VoiceEngine sources, 16 app sources, one Shared source, one widget source, 21 test files, and the package manifest. All source/test files were assigned to complete subsystem reviews; the primary reviewer separately traced affected callers, reviewed the state engine/tracker/tests, and verified the changes. `engineering-audit-coverage.md` lists the baseline inventory.

Also reviewed: README, license, ignore rules, support/privacy documents, Xcode project and scheme, plists, entitlements, privacy manifest, and asset-catalog metadata/references. Icon filenames resolve; PNG dimensions/formats were checked. Screenshots were treated as documentation assets, **not visual or accessibility QA**. No repo instruction files or configured lint/formatter/CI jobs were found in the tracked tree. No credentials or `.env` files were inspected. No upstream Hermes installation was changed or full upstream contract review performed; the README's contract date was intentionally preserved.

### Duplication and dead/unnecessary code removal

- **Canonical locking:** `FakeRecorder`'s throwing/nonthrowing `locked` overloads → one `rethrows` helper. All its existing property accessors and start/stop/cancel callbacks retain behavior.
- **Canonical provider URL validation:** duplicated permissive URL parsing in `DirectSTTConfig.init` and `DirectTTSConfig.init` → private `directVoiceBaseURL`. Both callers migrated; wire-specific fields remain separate.
- **Canonical JSON transcript extraction:** provider response handling now shares the `{text}` extraction before applying intentional per-wire fallback rules.
- Removed one redundant `await` and the redundant whitespace trim after split/join normalization.
- **No files, dependencies, exports, public APIs, or uncertain dynamically referenced code were deleted.** No claim that all declared-but-unreferenced public APIs are safe to remove.
